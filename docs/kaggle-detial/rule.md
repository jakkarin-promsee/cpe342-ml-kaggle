# Competition Rules

## 1. Team composition

- Maximum team size: **5 members**.

## 2. Data usage

- Use only the datasets provided for this competition. External datasets, web scraping, and supplementary data sources are prohibited.
- Data augmentation is allowed when applied to the provided training data.
- Only the Train and Validation sets may be used for model training or validation.
- Combining the Train and Validation sets for final model training is allowed after validation is complete.
- Do not use or execute any part of the Test set for training-related purposes, including pseudo-labeling or fine-tuning.

## 3. Model development

| Topic | Rule |
| --- | --- |
| Pre-trained models for Task 4 | Allowed (for example, ResNet, EfficientNet, or ViT) |
| Models for Tasks 1, 2, 3, and 5 | Train from scratch using only the provided data |
| Model ensembling | Allowed within these constraints |
| Feature engineering | Encouraged |
| AutoML frameworks | Prohibited (for example, AutoGluon, PyCaret, or H2O AutoML) |
| Hyperparameter optimization | Allowed (for example, GridSearchCV, RandomizedSearchCV, or Optuna) |

## 4. Collaboration and sharing

**During the competition:**

- Collaborate only with your team members.
- Conceptual discussion in the forum is welcome. Do not share solution-specific code or predictions there.

**After the competition:** Sharing code and methodology with classmates is encouraged.

## 5. Academic integrity

- Do not probe the Test set or attempt to reverse-engineer or obtain its labels.
- Follow daily submission limits to avoid leaderboard overfitting.
- All team members must make a substantial contribution.

## 6. Evaluation criteria

As part of CPE342 coursework, the competition is evaluated on:

- Leaderboard performance.
- Methodology quality and creativity.
- Understanding demonstrated in the final report and provided source code.

## 7. Violations

Rule violations may result in academic penalties under course policy.
